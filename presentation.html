Problem Statement & Industry Context

Why Traditional UI Testing Breaks Down

Modern responsive web applications require visual reasoning that conventional test runners cannot deliver.

1. Brittle DOM Selectors

  • Selenium and Cypress depend entirely on hardcoded XPath, IDs, or CSS classes.
  • A single class rename or Tailwind CSS refactor breaks test suites immediately.
  • Engineers waste 30%+ of testing time constantly updating test scripts.

2. Blind to Visual Bugs

  • Traditional frameworks only verify if an HTML tag exists in the DOM tree.
  • They completely miss buttons clipping off-screen on mobile viewports.
  • Horizontal scrollbar leaks, clipped text, and bad contrast pass undetected.

3. Slow Manual Triage

  • When visual bugs occur, engineers spend hours reproducing them across devices.
  • Writing and reviewing simple CSS patches causes release bottlenecks.
  • Lack of automated re-testing leads to recurring visual regressions.
Architecture Overview

OmniSight: The Self-Healing Closed Loop

A 4-stage pipeline that automates inspection, diagnosis, repair, and live verification.

1. Capture & Measure

  • Automated Playwright browser controller.
  • Dual-viewport capture: Desktop (1366x768) and Mobile (390x844).
  • Deep DOM layout metrics (bounding boxes, horizontal overflow).

2. Multimodal AI

  • Ingests compact viewport screenshots and DOM metrics.
  • Vision-Language Model (VLM) identifies visual layout defects.
  • Outputs validated, structured JSON schema with confidence scores.

3. Patch Generation

  • Synthesizes actionable CSS patches targeted to offending selectors.
  • Proposes safe styling rules (e.g. max-width, overflow-x).
  • Presents reviewable patch diffs in the QA dashboard.

4. Live Rescan Verify

  • Injects proposed CSS patch into live browser session.
  • Re-captures DOM metrics & responsive screenshots.
  • Verifies defect resolution (verified_resolved) without regressions.

Implementation Detail 1

Playwright Automation & DOM Metric Extraction

Extracting deep layout measurements that visual checks and unit tests cannot see.

Simultaneous Dual-Viewport Capture

  • Desktop Viewport: 1366 x 768 px (Standard 16:9 laptop display).
  • Mobile Viewport: 390 x 844 px (Modern mobile phone display).
  • Automated full-page screenshot capture saved directly to artifacts directory.
  • Clean naming scheme: {scan_id}_{viewport}.png for instant retrieval.
  • Resilient Navigation: navigate_with_retry with exponential backoff handles flaky networks.

Deep DOM Geometry Extraction

  • Button Coordinates: Queries button, a.btn, input[type=submit].
  • Bounding Boxes: Uses getBoundingClientRect() to extract x, y, width, height.
  • Off-Screen Detection: Evaluates rect.right > innerWidth || rect.left < 0.
  • Horizontal Overflow: Detects scrollWidth > clientWidth across viewports.
  • Hidden Controls: Discovers invisible controls ([hidden], display: none).
Implementation Detail 2

Asynchronous Processing & SQLite Persistence

Migrating from an in-memory prototype to an enterprise-grade persistent microservice.

Asynchronous Task Processing

  • Problem: Browser automation takes 3-10 seconds, causing gateway timeouts on sync HTTP calls.
  • Solution: Offloaded run_scan_worker to FastAPI BackgroundTasks.
  • Immediate Response: POST /api/scan creates a pending DB record and returns 202 Accepted.
  • Status Polling: GET /api/scans/{scan_id} provides real-time state: pending → processing → completed.
  • Eliminates server blocking and allows parallel queuing.

SQLAlchemy ORM + SQLite Storage

  • Dedicated database.py module with clean SessionLocal transaction management.
  • ScanRecord Table: Persists scan_id, target URL, status, viewports, JSON results, and error logs.
  • Automatic Timestamps: Tracks created_at and completed_at using UTC timezone.
  • Persistent History: GET /api/scans queries SQLite database ordered by recency.
  • Model Serialization: to_dict() formats responses and calculates detected issues.
Implementation Detail 3

Self-Healing Rescan Loop & Security Hardening

Closing the loop with CSS patch injection and enforcing strict enterprise safeguards.

Closed-Loop Verification Engine

  • POST /api/rescan: Accepts target URL + proposed CSS patch.
  • Live Injection: Playwright injects CSS rules directly via page.add_style_tag().
  • Deterministic Re-Evaluation: Re-evaluates overflow and off-screen buttons on modified DOM.
  • Outcome Classification: Automatically marks status as verified_resolved or verification_failed.
  • POST /api/verify_fix: Provides complete contract compatibility for frontend api.js.

Enterprise Security & Observability

  • SSRF Protection: Enforces strict ALLOWED_DOMAINS allowlist (localhost, 127.0.0.1).
  • Blocks internal network probing and malicious external URLs with 400 Bad Request.
  • Custom Middleware: Measures execution duration and injects X-Process-Time header.
  • Distributed Tracing: Assigns unique UUID X-Request-ID to every request for audit trails.
  • Artifact Cleanup: DELETE /api/artifacts/clean frees server disk space safely.
